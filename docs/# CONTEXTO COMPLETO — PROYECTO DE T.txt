## 3. CONTEXTO DEL PROBLEMA QUE RESUELVE EL SISTEMA

### Situación actual (problema)
Las empresas industriales de la región de Monclova, Coahuila que tienen certificación ISO 14001 deben capacitar periódicamente a sus empleados en temas de gestión ambiental. Este proceso actualmente se hace de forma **manual o semi-digitalizada** (papel, Excel, archivos dispersos), lo que genera:

- Duplicidad y pérdida de registros
- Dificultad para consultar historiales de capacitación
- Tiempo excesivo preparando evidencias para auditorías
- Errores humanos y omisiones en la actualización de información
- Seguimiento deficiente del cumplimiento del personal

### Situación deseada (solución)
Una plataforma web que gestione de forma integral:
- Registro de empleados y asignación de cursos
- Aplicación de evaluaciones digitales con calificación automática
- Almacenamiento centralizado de resultados y evidencias
- Generación automática de reportes PDF para auditorías ISO 14001
- Historial de cumplimiento por empleado y por área

### Norma de referencia
**ISO 14001** — Sistema de Gestión Ambiental. Las cláusulas más relevantes para este proyecto son:
- **Cláusula 7.2** — Competencia del personal
- **Cláusula 7.3** — Toma de conciencia ambiental

### Contexto de validación
El alumno tiene **familiares o conocidos en empresas industriales de Monclova** que pueden proveer información real sobre cómo aplican actualmente la ISO 14001. Esto es suficiente para justificar los requerimientos del sistema y para hacer una validación básica con usuarios reales.

## 5. MÓDULOS DEL SISTEMA (MVP)

Estos son los 5 módulos mínimos para una defensa exitosa. No agregar más sin consultar si el tiempo lo permite.

### Módulo 1 — Gestión de usuarios y roles
- Roles: Administrador, Instructor, Empleado
- Login con usuario y contraseña (JWT)
- El admin gestiona todo; el empleado solo ve sus cursos y exámenes asignados
- CRUD de empleados con datos: nombre, área/departamento, puesto, correo

### Módulo 2 — Gestión de cursos
- El admin/instructor crea cursos: nombre, descripción, objetivo, material (texto enriquecido o PDF adjunto)
- Asignación de cursos a empleados individuales o por área completa
- Control de fechas: fecha de asignación y fecha límite de cumplimiento
- Estados: Pendiente / En progreso / Completado / Vencido

### Módulo 3 — Evaluaciones digitales
- Banco de preguntas tipo opción múltiple (mínimo 4 opciones, 1 correcta)
- El instructor asocia un examen a un curso
- El empleado responde el examen en la plataforma en una sola sesión
- El sistema califica automáticamente, guarda: puntuación, fecha, hora, intentos
- Porcentaje mínimo aprobatorio configurable por curso (ej: 70%)

### Módulo 4 — Historial y seguimiento de cumplimiento
- Dashboard del admin con: total de empleados, cursos completados, cursos pendientes, tasa de cumplimiento
- Tabla filtrable por: área, estado (completado/pendiente/vencido), fecha
- Vista individual del empleado: todos sus cursos con estado y calificación
- Alertas visuales de cursos próximos a vencer

### Módulo 5 — Generación de reportes PDF ⭐
- **Este es el módulo más importante para la justificación ISO 14001**
- Reporte individual: historial completo de un empleado (cursos, fechas, calificaciones, estado)
- Reporte por área: cumplimiento de todo un departamento
- Reporte general: panorama de toda la empresa
- El PDF debe verse formal: logo de la empresa, fecha de generación, firma de responsable
- Descargable con un solo clic desde la plataforma

## 9. PREGUNTAS DIFÍCILES DE SINODALES Y CÓMO RESPONDERLAS

Estas son las preguntas más comunes que pueden hacer y la estrategia de respuesta:

**"¿Por qué no usaron una plataforma existente como Moodle o Google Classroom?"**
→ Esas plataformas son generalistas y no están diseñadas para cumplimiento normativo ISO 14001. No generan los reportes específicos que requiere una auditoría, no manejan vigencias de capacitación ambiental ni se integran con los registros de evidencia que exige la norma.

**"¿Cómo validaron que el sistema resuelve el problema real?"**
→ Se realizaron entrevistas con personal de empresas industriales con certificación ISO 14001 en Monclova para identificar los requerimientos, y se hizo una sesión de validación con usuarios reales al final del desarrollo.

**"¿Por qué FastAPI en lugar de Django o Node.js?"**
→ FastAPI genera documentación automática (Swagger/OpenAPI), tiene validación de datos nativa con Pydantic, es más ligero que Django para una API REST, y el equipo de desarrollo ya tenía experiencia con él.

**"¿El sistema está en producción o es solo un prototipo?"**
→ Es un prototipo funcional desplegado en un entorno de pruebas (Railway). El siguiente paso sería una fase de implementación real que incluiría pruebas de seguridad, integración con sistemas de RRHH existentes y capacitación al personal.

**"¿Qué tan escalable es el sistema?"**
→ La arquitectura en capas (API → Services → Repositories → Models) permite agregar módulos sin reescribir el sistema. La migración de SQLite a PostgreSQL para producción está contemplada. Se pueden agregar tipos de negocio, más normas ISO, o módulos de capacitación para otras áreas.
